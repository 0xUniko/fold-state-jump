# Project-local cache locations

`src/cache-location.ts` selects storage independently of compilation identity.
No cache directory is incorporated into BuildIdentity or declaration IDs, and
moving storage does not bypass dependency validation. The old global `ast-v2`
directory is not imported. Its snapshots age out only through user cleanup.

`resolveCacheProject(source, workspaceRoots)` requires an absolute source path.
It canonicalizes the source directory, examines ancestors from nearest to
farthest, and selects a Git root identified by a `.git` directory with `HEAD`,
or a `.git` file pointing to a Git directory with `HEAD`. This covers ordinary
repositories, submodules, nested repositories, and linked worktrees. A worktree
uses its own source root, never the Git common directory. Empty or malformed
markers are ignored. An unreadable marker creates an explicit
`UnreadableGitProject` boundary at that directory, preserving nested-project
isolation instead of accidentally selecting an outer repository. If there is no Git root, the longest containing canonical
workspace root wins; without one, the source directory wins. Sibling workspaces
are excluded using path components. Process cwd and compilation cwd never enter
the selection. Symlinked directory aliases resolve to the same project key.

`prepareCacheLocation({ source, workspaceRoots, globalStorage, configuredPath })`
returns one of four explicit cases:

| Case | Root directory |
| --- | --- |
| `ProjectLocalCache` | `<project>/.cache/fold-state-jump` |
| `ConfiguredCache` | `<configured base>/<SHA-256 of canonical project root>` |
| `GlobalFallbackCache` | `<globalStorage>/project-cache-v2/<project hash>` |
| `UnavailableCache` | None; disable persistence and retain native/RAM results |

Available cases contain `astDirectory = <root>/ast` and project identity. Custom
relative paths resolve against the selected project root. Custom paths are
always bases: hashing below them prevents two projects sharing a configured
directory from clearing each other's files. Fallback retains the failed preferred
location and reason for diagnostics. A failed fallback returns `UnavailableCache`
instead of failing analysis. No `pch` directory is created by this module.

Preparation creates private directories, writes the exact generated ignore file,
and checks writability in the actual AST destination using a short-lived unique
directory. The ignore file contains:

```gitignore
# This file is autogenerated by fold-state-jump.
*
```

The generated file ignores itself. Root `.gitignore` and `.git/info/exclude`
are untouched. Opening the generated file refuses symlinks, so an existing link
to a source-controlled ignore file cannot be overwritten. A failed preparation
falls back to the per-project global directory. Runtime disk-cache instances
should be shared by `astDirectory` so writes and clear use the same permit.
Preparation belongs on disk restore/write paths, not valid memory hits.

`test/cache-location.test.ts` uses real Git repositories and a linked worktree.
It verifies Git status, nested roots, containing/sibling workspaces, standalone
sources, source aliases, malformed markers, ignore-file symlinks, relative and
absolute custom bases, independent fallback directories, unavailable storage,
and actual read-only permissions (the permission test skips UID 0). Tests run
on Linux with Bun using Node's test API; no VS Code host is required.
Windows path/permission behavior has not been exercised. An unreadable Git
metadata marker cannot be validated, so its containing directory is treated as
a conservative project boundary rather than claiming that Git metadata is valid.
Dependency and BuildIdentity validation remain required for every cache hit.
